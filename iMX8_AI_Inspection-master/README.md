# 🔬 Semiconductor Wafer Defect Segmentation Pipeline

ระบบอัตโนมัติสำหรับการแบ่งส่วนภาพ (Segmentation), ตรวจวัดกฎฟิสิกส์ (Physical Inspection), และประเมินเปรียบเทียบประสิทธิภาพโมเดลวิเคราะห์รอยโรค/สิ่งบกพร่องบนแผ่นเวเฟอร์ (Semiconductor Wafers) รองรับโมเดลหลากหลายสถาปัตยกรรม (Standard U-Net PyTorch/Keras, ResNet34-UNet, และ YOLOv8-seg)

## 💻 อธิบายโหมดการทำงานทั้งหมดในระบบ (Main Menu Options)

เมื่อเปิดโปรแกรมผ่าน `./run.sh` ระบบจะแสดงเมนูการใช้งานทั้งหมด 7 ข้อ ดังนี้:

### [0] Wafer Pipeline Configuration (ตั้งค่าคลาสใช้งาน และ เลือกโมเดลที่ใช้งาน)
โหมดตั้งค่าสถาปัตยกรรมของไปป์ไลน์แบบเรียลไทม์ มีคุณสมบัติดังนี้:
*   **ระบบล็อกคลาสสำคัญ (Locked Classes):** คลาส `pad` (1) และ `probemark` (2) จะถูกบังคับเปิดใช้งานเสมอเพื่อความเสถียรของเกณฑ์ตัดสินกฎฟิสิกส์ (ผู้ใช้ไม่สามารถกดปิดได้)
*   **ระบบสลับคลาสอัตโนมัติ (Auto-resolved Weights):** ผู้ใช้สามารถกดสลับเปิด/ปิดคลาส `grain` (3) ได้อย่างอิสระ เมื่อสถานะการเปิดใช้งานคลาสเปลี่ยน (จาก 2 คลาสเป็น 3 คลาส หรือในทางกลับกัน) ระบบจะ**เปลี่ยนพิกัดชี้ไฟล์น้ำหนักโมเดล (Weights)** ของโมเดล PyTorch U-Net, Keras U-Net, ResNet-UNet, และ YOLOv8-seg ให้ชี้ไปยังไฟล์ของโฟลเดอร์ `models/2class/weights` หรือ `models/3class/weights` ให้โดยอัตกโนมัติทันที ป้องกันปัญหาขนาดมิติโมเดลขัดข้อง (Shape Mismatch Error)

### [1] Dataset & Annotations Tools (จัดการภาพป้ายกำกับ JSON/TXT, เปลี่ยนชื่อคลาส)
รวบรวมเครื่องมือจัดการข้อมูลดิบก่อนนำไปฝึกสอนโมเดล:
*   **Convert JSON to Mask:** แปลงพิกัดแบบโพลีกอนจากไฟล์ LabelMe JSON ออกมาเป็นรูปภาพหน้ากากระดับเทา (Grayscale Mask PNG)
*   **Split Dataset:** สุ่มแบ่งรูปภาพดิบและไฟล์ป้ายกำกับออกเป็นชุดสำหรับฝึกสอน (Train) และชุดสำหรับทดสอบ (Val) ในอัตราส่วน 80:20
*   **Convert masks to YOLO TXT format:** แปลงรูปภาพ Mask ออกเป็นพิกัดคลาสแบบ Text File ตามข้อกำหนดของโมเดล YOLOv8-seg

### [2] Run U-Net Models (Standard PyTorch / Keras)
โหมดสำหรับจัดการโมเดล U-Net แบบดั้งเดิม:
*   **Training U-Net:** สั่งเทรนโมเดล U-Net บน PyTorch หรือ Keras/TensorFlow ตามค่าพารามิเตอร์ที่กำหนดใน Config
*   **Inference/Prediction:** ทำนายผลแบ่งส่วนภาพของแผ่นเวเฟอร์ทีละภาพหรือทำแบบทีละกลุ่มโฟลเดอร์ (Batch)

### [3] Run ResNet-UNet (Pretrained Backbone)
โหมดรันโมเดลที่ใช้โครงข่าย ResNet34 เป็น Backbone ในการสกัดคุณลักษณะ (Feature Extraction):
*   มีประสิทธิภาพการประมวลผลขอบเขตที่ดีขึ้นอย่างเห็นได้ชัดผ่านโมเดลที่ผ่านการฝึกฝนมาล่วงหน้า (Pretrained Backbone)

### [4] Run YOLOv8-seg & Inspection Rules (เทรน YOLO / รันกฎเกณฑ์ตรวจวัดแผ่น)
โหมดสำหรับสั่งเทรนโมเดล YOLOv8-seg หรือรันระบบตรวจสอบตัดสินคุณภาพแผ่นเวเฟอร์ (Wafer Defect Inspection Engine) ด้วยกฎฟิสิกส์

### [5] Accuracy Evaluation & Comparison (วัดและพล็อตกราฟเปรียบเทียบ IoU)
ระบบวัดประเมินประสิทธิภาพอัตโนมัติ โดยโปรแกรมจะดึงรูปภาพ Validation ทั้งหมดจำนวน 300 รูปมารันทำนายผลเปรียบเทียบกันระหว่าง PyTorch U-Net, Keras U-Net, ResNet-UNet, และ YOLOv8-seg เพื่อรายงานค่าเฉลี่ยความถูกต้อง (Accuracy), mIoU, Precision, Recall, F1-Score และพล็อตตาราง Confusion Matrix ของพิกเซล

## 📏 หลักการการเช็คเงื่อนไขทางฟิสิกส์ (Physical Wafer Inspection Rules)

เมื่อเปิดใช้งาน **Wafer Inspection** ระบบจะดึงพิกัดที่โมเดลทำนายได้ (Pads, Probemarks, Grains) และนำมาประเมินผ่านตัวแปรเกณฑ์ตัดสินใน [inspection_rules.yaml](file:///home/nxp1/Desktop/PUNPUNJA/PROJECT/CASE_UNET/configs/inspection_rules.yaml) โดยมีหลักการทำงานอย่างละเอียดดังนี้:

### 1. หลักการขึงขอบเขตแผ่นด้วย Convex Hull (สำหรับโมเดลแบบ Semantic)
*   **ปัญหา:** โมเดลประเภท Semantic Segmentation (U-Net, ResNet) ประมวลผลคลาสระดับพิกเซลแบบแบ่งขาด พิกเซลที่เป็นรอยเข็ม (Probemark) จึงไม่สามารถทับซ้อนกับคลาสแผ่น (Pad) ได้ ทำให้เกิดช่องว่าง/รูโหว่ตรงกลางแผ่น Pad ส่งผลให้คำนวณพื้นที่ทับซ้อนได้เป็น `0%`
*   **หลักการเช็ค:** ระบบประยุกต์ใช้แนวคิด **Convex Hull** (ขอบเขตนูนต่ำต่ำสุดที่ล้อมรอบวัตถุ) มาล้อมคอนทัวร์ของ Pad ก่อนทำการเช็ค ช่วยขึงผิวบริเวณรูโหว่และร่องแหว่งทั้งหมดให้ทึบตันชั่วคราว ทำให้หาพื้นที่ส่วนทับซ้อนร่วมกับรอยเข็มได้อย่างถูกต้องแม่นยำ 100%

### 2. หลักการจับคู่ด้วยสัดส่วนการทับซ้อน (Overlap Matching - `min_overlap_pct`)
*   แผ่นเวเฟอร์หนึ่งภาพอาจมี Pad หลายแผ่นและรอยกดเข็มหลายจุด 
*   ระบบจะทำการหาค่าความชนกัน (Intersection) ระหว่างรอยกดเข็มแต่ละอันกับทุก ๆ แผ่น Pad
*   รอยกดเข็มจะถูก**จับคู่กับ Pad** แผ่นนั้น ๆ ก็ต่อเมื่อมีพื้นที่ทับซ้อนกันมากกว่าหรือเท่ากับค่าเกณฑ์ตัดสิน (ค่าเริ่มต้นคือ **`50%`** หรือ `0.5`) หากทับซ้อนน้อยกว่าเกณฑ์ จะถูกตัดออกเป็นสัญญาณรบกวน (Noise)

### 3. หลักการวัดระยะชิดขอบด้วย Distance Transform
*   **ปัญหา:** การคำนวณระยะห่างระหว่างจุดต่อจุดของของขอบโพลีกอนมีความซับซ้อนและกินเวลาสูง $O(N^2)$ และมีปัญหากับวัตถุที่ไม่ใช่รูปทรงนูน (Non-convex Shapes)
*   **หลักการเช็ค:** ระบบประยุกต์ใช้ฟังก์ชัน **Distance Transform** (`cv2.distanceTransform`) บนหน้ากากของ Pad โดยพิกเซลที่อยู่ขอบนอกของ Pad จะมีค่าระยะทางเป็น `0` และเพิ่มค่าขึ้นเรื่อย ๆ เมื่อเข้าสู่ศูนย์กลางแผ่น 
*   พิกัดพิกเซลขอบนอกสุดของ Probemark จะวิ่งไปตรวจเช็คค่าความสว่างบนแผนที่ระยะทางของ Pad
    *   **FAIL:** หากระยะสั้นที่สุดระหว่างรอยเข็มถึงขอบแผ่นมีค่าต่ำกว่า **`fail_distance_um`** (ค่าเริ่มต้นคือ `8.0 um`)
    *   **WARNING:** หากอยู่ระหว่างช่วงรอยต่อภัยพิบัติขอบเขต **`fail_distance_um`** ถึง **`fail_distance_um + warning_distance_um`**
    *   **PASS:** หากระยะอยู่ห่างปลอดภัยเกินขอบเขตข้างต้น

```
[  PAD AREA  ]  <--- warning_dist (3um) ---> [ FAIL_DIST (8um) ] ---> | (ขอบ PAD)
(ปลอดภัย: PASS)         (เตือน: WARNING)           (ชิดเกินไป: FAIL)
```

### 4. หลักการประเมินขนาดสัดส่วนพื้นที่ (Area Ratio Check)
*   คำนวณพื้นที่รวมของพิกเซลรอยกดเข็มทั้งหมดที่อยู่บนแผ่น Pad เดียวกันเทียบกับพื้นที่จริงทั้งหมดของแผ่น Pad นั้น ๆ
*   **FAIL (ใหญ่เกินไป):** หากสัดส่วนเกินค่า **`max_area_ratio_pct`** (ค่าเริ่มต้นคือ `25.0%`) บ่งบอกว่าเข็มเกิดความเสียหายหรือกดกระแทกแรงเกินไป
*   **FAIL (เล็กเกินไป):** หากสัดส่วนต่ำกว่าค่า **`min_area_ratio_pct`** (หากตั้งไว้) บ่งบอกว่ารอยกดเข็มอาจทำนายออกมาไม่ครบ

### 5. หลักการพิจารณารอยเข็มสูญหาย (Missing Mark Action)
*   หากตรวจพบแผ่น Pad อยู่ในภาพ แต่ไม่มีรอยกดเข็ม (Probemark) ใด ๆ มาจับคู่ทับซ้อนอยู่เลย
*   ระบบจะทำการตัดสินใจตามตัวแปรตั้งค่า **`missing_mark_action`**:
    *   **`warning`** (ค่าเริ่มต้น): เปลี่ยนสถานะการตัดสินของภาพเป็นสีเหลืองเตือนภัยพิบัติ เพื่อให้คนมาตรวจสอบหน้างาน
    *   **`fail`**: ตัดสินเป็นชิ้นงานเสียหาย (FAIL) ทันที

### 6. หลักการกรองตำแหน่งด้วย Region of Interest (ROI)
*   แผ่น Pad ที่อยู่บริเวณขอบภาพมากเกินไปอาจโดนตัดครึ่งรูป ทำให้รูปทรงบิดเบี้ยวและประมวลผลผิดพลาด
*   ระบบใช้ค่าเกณฑ์สัดส่วน ROI **`v_roi`** และ **`h_roi`** (ค่าเริ่มต้น `0.7`) เพื่อสร้างพื้นที่กรอบตรวจสอบตรงใจกลางภาพ และละเว้นการประเมินแผ่น Pad ใด ๆ ที่หลุดอยู่นอกพื้นที่ปลอดภัยนี้

*   เมื่อสั่งทำนายภาพด้วยโมเดลแบบ Semantic ระบบจะทำการผสานพื้นที่ทำนายคลาส Pad ร่วมกับรอยกดเข็มและเศษฝุ่นก่อนบันทึก ทำให้เวลาเปิดดูไฟล์ `.json` ผลลัพธ์ในแอป LabelMe แผ่น Pad จะแสดงผลเป็นรูปทรงทึบตันเต็มแผ่นสวยงาม ไม่แหว่งเว้าเป็น C-Shape หรือโดนเจาะรูตรงกลาง ซึ่งสอดคล้องกับมาตรฐานการติดป้ายกำกับของมนุษย์
